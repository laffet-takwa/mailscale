# Testing guide

## Test pyramid

| Layer | Tool | Runs against | Command |
| --- | --- | --- | --- |
| Java unit + domain | JUnit 5, Mockito | none | `mvn -f backend-java/pom.xml test` |
| Java integration | Spring Boot Test, H2 | in-memory PostgreSQL-mode DB | same as above (profile `test`) |
| Kotlin unit | JUnit 5, MockK | none | `gradlew -p worker-kotlin test` |
| Frontend unit | Vitest, React Testing Library | jsdom | `npm --prefix frontend test` |
| End-to-end | Playwright | real stack | `npx playwright -c e2e-tests test` |
| Load | k6 | running API | `k6 run load-tests/transactional.js` |

## What is covered

### Backend (JUnit 5 + Mockito, no infrastructure)

- `EmailMessageTest` - status transitions and terminal-state protection,
  deterministic idempotent UUID derivation
- `CampaignTest` - DRAFT -> SCHEDULED -> PROCESSING -> COMPLETED/CANCELLED/FAILED
  and rejected transitions
- `ContactTest` - unsubscribe/resubscribe and deliverability rules
- `ApiKeyTest` - active/expired/revoked states
- `JwtServiceTest` - round-trip, tampered tokens, wrong secret, weak-secret
  handling
- `TemplateServiceRenderTest` - variable rendering, HTML escaping, repeated
  tokens, unknown-token safety

### Backend integration (Spring Boot Test + H2)

- `AuthFlowIntegrationTest` - registration, duplicate email, login, bad password
- `ContactServiceIntegrationTest` - CRUD, duplicate email, CSV import
  dedup/error reporting, pagination
- `CampaignServiceIntegrationTest` - create, validate, schedule, dispatch,
  reject unscheduled dispatch, template versioning and preview
- `TransactionalEmailIntegrationTest` - queue + outbox + idempotency record in
  one transaction, same-key replay, conflicting key reuse, missing key,
  suppressed recipient

### Kotlin worker

- `RetryPolicyTest` - exponential cap, jitter bounds, non-positive protection,
  attempt arithmetic, invalid config
- `SmtpErrorClassifierTest` - 4xx/5xx, timeouts, IO errors, keyword
  classification, email validation
- `RateLimiterTest` - permit exhaustion and utilisation
- `MessageProcessorTest` - delivery, suppression, consent, already-terminal
  skip, transient retry, permanent failure after max attempts

### Frontend

- `utils.test.ts` - error extraction, date/percent formatting, class merging
- `ui.test.tsx` - Button/Input/Spinner/Badge/Alert behaviour and accessibility
- `components.test.tsx` - DataTable rendering/empty state, EmptyState, Card
- `LoginPage.test.tsx` - render, email validation, password validation, link,
  submit guard

## Testcontainers

Integration tests requiring real PostgreSQL use the `integration` profile:

```bash
./mvnw -f backend-java/pom.xml verify -Pintegration
```

Docker must be running. Tests tagged `integration` are excluded from the
default `mvn test` run so the suite works in environments without Docker.

## Coverage

No coverage percentage is claimed unless generated by an actual report. To
produce one:

```bash
./mvnw -f backend-java/pom.xml test jacoco:report
```

## E2E

```bash
cd e2e-tests
npm install
npx playwright install chromium
npx playwright test
```

Requires the full stack (API + PostgreSQL + frontend) running locally.
