# Development guide

## Prerequisites

- JDK 21+ (builds with Temurin 21; 25 also works)
- Node.js 20+
- Docker + Docker Compose

## Option A: Docker everything

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
```

Services:

| Service | URL |
| --- | --- |
| React SPA | http://localhost:5173 |
| Java API | http://localhost:8080 |
| API docs (Swagger) | http://localhost:8080/swagger-ui.html |
| Worker metrics | http://localhost:8081/metrics |
| Mailpit (test SMTP) | http://localhost:8025 |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3000 (admin / admin) |
| PostgreSQL | localhost:5432 |
| Redis | localhost:6379 |
| Kafka | localhost:9092 |

## Option B: Run services locally

Start the infrastructure only:

```bash
docker compose up -d postgres redis kafka mailpit
```

Build and run the API:

```bash
./mvnw -f backend-java/pom.xml spring-boot:run
```

Run the Kotlin worker:

```bash
./gradlew -p worker-kotlin run
```

Run the frontend:

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

## Demo login

| Email | Password |
| --- | --- |
| admin@mailscale.local | demo1234 |

The demo data (organization, admin user, template, segment, tags, and three
contacts) is seeded by `DemoDataInitializer` when
`MAILSCALE_DEMO_SEED_ENABLED=true` (the default). The admin password BCrypt
hash is generated at runtime, so no credentials are committed.

## Environment variables

See `.env.example` for the full list. The most important:

| Variable | Default | Purpose |
| --- | --- | --- |
| `MAILSCALE_JWT_SECRET` | dev value | JWT signing secret |
| `SPRING_DATASOURCE_*` | localhost:5432 | PostgreSQL connection |
| `KAFKA_BOOTSTRAP_SERVERS` | localhost:9092 | Kafka brokers |
| `MAIL_PROVID` | `mock` | `mock` (no email sent) or `smtp` |
| `MAIL_SMTP_HOST` / `MAIL_SMTP_PORT` | localhost:1025 | Mailpit |
| `AI_PROVIDER` | `mock` | `mock` (offline) or `openai-compatible` |
| `AI_API_KEY` | - | Only required for real LLM calls |

## Resetting local state

```bash
docker compose down -v            # drop volumes (database, prometheus)
./gradlew -p worker-kotlin clean  # clear worker build output
rm -rf backend-java/target
```

## Troubleshooting

**API cannot reach PostgreSQL.** Confirm the container is healthy:
`docker compose ps postgres`. The default profile expects
`jdbc:postgresql://localhost:5432/mailscale`.

**Flyway migration failed.** Migrations are portable SQL. If you use the
`sqlserver` profile, check `docs/adr/0005-postgres-sqlserver.md`.

**Kafka connection refused.** The API and worker both need
`KAFKA_BOOTSTRAP_SERVERS` pointing at the same broker. Topic creation is done
by the API at startup (`KafkaAdmin`).

**No email appears in Mailpit.** Set `MAIL_PROVID=smtp` on the worker. With
the default `mock` provider no SMTP traffic is generated by design.

**Worker starts but does not consume.** The worker uses consumer group
`mailscale-worker`; check `localhost:8081/metrics` for lag. Reset the group by
running with a new `WORKER_CONSUMER_GROUP`.

**Redis rate limit errors.** Rate limiting is skipped when Redis is not
configured (test profile), so a failing `/api/v1/emails` request is not
typically caused by Redis unless `mailscale.mail.rate-limit-per-minute` is
very low.
